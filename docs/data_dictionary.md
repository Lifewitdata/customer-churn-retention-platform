# Data dictionary

Primary feed: `data/raw/WA_Fn-UseC_-Telco-Customer-Churn.csv` (IBM Telco Customer Churn snapshot), 7,043 rows x 21 columns.
Second feed: `data/raw/ibm_telco_11_1_3/` - see its PROVENANCE.md and the section at the bottom of this file.

Generated by `python src/make_data_dictionary.py`. Every count and range below is read from the CSV on each run; only the meaning of a field is hand-written.

Model inputs actually used: 16 categorical (`gender`, `Partner`, `Dependents`, `PhoneService`, `MultipleLines`, `InternetService`, `OnlineSecurity`, `OnlineBackup`, `DeviceProtection`, `TechSupport`, `StreamingTV`, `StreamingMovies`, `Contract`, `PaperlessBilling`, `PaymentMethod`, `tenure_band`) and 16 numeric (`SeniorCitizen`, `tenure`, `MonthlyCharges`, `TotalCharges`, `service_count`, `avg_monthly_spend`, `bill_shock_pct`, `bill_shock_flag`, `no_support_flag`, `no_security_flag`, `contract_risk`, `electronic_check_flag`, `is_new`, `charges_per_service`, `contract_remaining_proxy`, `log_total_charges`). `gender` and `customerID` are deliberately out.

## Blank TotalCharges - read this before casting anything

11 rows have a blank `TotalCharges` (not 0, not NaN - a single space character). Every one of them has tenure = 0, so they are brand-new customers who have not yet billed. Consequences:
- `pd.read_csv` with default settings turns ' ' into NaN and the rows look like missing data. This repo reads the CSV with `dtype=str, keep_default_na=False` so the blank stays visible, then coerces deliberately (`features.coerce_numeric`).
- `features.engineer()` fills those blanks with 0. That is a business rule, not a cleansing reflex; the DQ check `blank_TotalCharges_only_tenure_0` fails if a blank ever lands on a tenured customer.

## Engineered features (not in the raw file)

| feature | definition | sourced from | note |
|---|---|---|---|
| `service_count` | count of the 9 service/add-on columns equal to 'Yes' | PhoneService..StreamingMovies | Breadth of the bundle. Deeply protective: each add-on raises switching cost. |
| `avg_monthly_spend` | TotalCharges / tenure, falling back to MonthlyCharges at tenure 0 | TotalCharges, tenure, MonthlyCharges | Realised spend per month, which differs from the contracted MonthlyCharges whenever there are one-off charges. |
| `bill_shock_pct` | (MonthlyCharges - avg_monthly_spend) / avg_monthly_spend, 0 where the denominator is 0 | MonthlyCharges, avg_monthly_spend | PROXY. A true bill-shock needs a prior-month bill; this approximates it as 'this month costs more than the customer's own history'. |
| `bill_shock_flag` | bill_shock_pct > 0.20 | bill_shock_pct | Discretised shock, the form the Cox model and the FastAPI action rules use. |
| `no_support_flag` | TechSupport == 'No' | TechSupport | Absence of tech support is the cheapest protective add-on to sell. Caveat worth knowing: 'No internet service' is NOT counted as 1, so the 0 group mixes real have-support (15.2% churn) with no-internet (7.4%) - the flag is protective partly because it absorbs the no-internet cohort. |
| `no_security_flag` | OnlineSecurity == 'No' | OnlineSecurity |  |
| `contract_risk` | Month-to-month=2, One year=1, Two year=0 | Contract | Ordinal encoding of lock-in. Keeps contract as one monotone term for the Cox model. |
| `electronic_check_flag` | PaymentMethod == 'Electronic check' | PaymentMethod | No auto-debit means nothing stops the customer leaving mid-cycle. |
| `is_new` | tenure <= 12 | tenure | First-year cohort, where onboarding failure shows up. |
| `charges_per_service` | MonthlyCharges / max(service_count, 1) | MonthlyCharges, service_count | Price per bundled item - 'am I paying a lot for little?' proxy. |
| `contract_remaining_proxy` | 12 - (tenure % 12) for One year, 24 - (tenure % 24) for Two year, else 0 | Contract, tenure | PROXY, and the weakest one. There is no signup date in this dataset, so time-into-term is inferred by wrapping tenure. It is only meaningful if contracts started at tenure 0. |
| `log_total_charges` | ln(1 + TotalCharges) | TotalCharges | Heavy right tail compressed. |
| `tenure_band` | cut(tenure, [-1,12,24,48,72]) into 0-12 / 13-24 / 25-48 / 49-72 | tenure | Categorical view of loyalty, used for segment reporting and fairness. |
| `target` | Churn == 'Yes' -> 1 | Churn | Binary label. |
| `risk_tier` | High >= 0.60, Medium >= 0.35, else Low, on calibrated probability | churn_probability | Operating decision; the cutoffs are a business choice, not model output. |
| `churn_probability` | predict_proba from model_calibrated.pkl (isotonic-calibrated) | all 16 model features | Deployed scoring column. Calibration is why 0.60 means ~60%. |

These are not in the 21-column primary feed. They come from IBM's 'Telco customer churn (11.1.3+)' release and are used for enrichment and cross-source reconciliation only - the model never sees them.
